Your own cloud, explained like a building

These tools together make a private cloud: your own data centre that works like AWS or Azure, but on servers you own, including NVIDIA GPUs for AI. Each tool has one job. Click any floor to see what it does and who it talks to.

How it gets built, in order

You build from the ground up, the same way you would build a house. Each step uses the one before it.

  1. Rack the hardware

    Servers, network switches and GPU servers (for example NVIDIA HGX or servers with L40S / H100 cards) go into racks and get cabled. Each server has a management port (IPMI/Redfish) so it can be switched on remotely.

    Who: data centre team

  2. MAAS finds and installs the servers

    MAAS listens on the network. When a server powers on, MAAS discovers it, checks its CPU, memory, disks and GPUs, and installs Ubuntu Server on it automatically. No USB sticks, no manual installs.

    Who: platform team, once per server

  3. Juju installs the big software

    Juju takes those fresh Ubuntu machines and installs software using "charms" (ready-made recipes). It deploys Ceph first, then OpenStack and Kubernetes, and connects them to each other.

    Who: platform team

  4. Ceph turns all the disks into one pool

    Disks from many servers become one big, self-healing storage system. It gives disks to virtual machines, volumes to containers, and S3-style object storage for files and AI datasets.

  5. OpenStack and Kubernetes come online

    OpenStack lets teams create virtual machines, networks and firewalls with a click or an API call. Kubernetes runs containerised apps and scales them up and down. Kubernetes can run directly on servers or inside OpenStack VMs.

  6. Lock it down

    Keycloak becomes the single login for everything. Vault stores passwords, keys and certificates. PAM controls and records admin access. The SIEM collects security logs from all of it.

    Who: security team with platform team

  7. Turn on the lights and cameras

    Prometheus collects numbers (CPU, disk, GPU temperature), a log tool (Loki, OpenSearch or Elasticsearch) collects text logs, and Grafana shows both on dashboards with alerts.

  8. Hand it to developers through pipelines

    Azure DevOps (or GitLab / GitHub Actions / Jenkins) runs Terraform and Ansible to create and configure resources, and ships apps into Kubernetes. From now on, changes happen through code, not by hand.

    Who: everyone, every day

Who is allowed in, and who is watching

Security is not one tool. Four tools each guard a different door, and the SIEM watches all of the doors at once.

How the platform watches itself

There are two kinds of signals. Numbers ("disk is 91% full") go to Prometheus. Text ("error: connection refused") goes to the log tool. Grafana puts both on one screen.

How the GPUs reach the workloads

GPUs are expensive, so the platform shares them carefully. There are two doors to a GPU, depending on whether the job runs in a container or a virtual machine.

How it runs day to day

After launch, the platform runs in a loop. Nobody logs into a server to "just fix it"; every change goes through code and the pipeline, so it is reviewed, repeatable and logged.

Adding capacity

Plug in a new server. MAAS installs Ubuntu, then one Juju command adds it to Ceph, OpenStack or Kubernetes. The new space or compute shows up in minutes.

A disk or server dies

Ceph keeps 3 copies of data and rebuilds the missing copy on its own. Kubernetes restarts containers on healthy machines. Grafana shows what happened; you replace the part when convenient.

Upgrades and patches

Juju upgrades OpenStack, Kubernetes and Ceph one piece at a time with no big outage. Ubuntu security patches roll out through Ansible or Canonical's Landscape and Livepatch.

Access reviews

Leavers are removed once in Keycloak and lose access everywhere. Vault rotates secrets automatically. PAM recordings and SIEM reports feed audits.

Terraform vs Ansible vs Juju, without the confusion

All three "automate", which is why people mix them up. The difference is what each one is responsible for.

ToolIn simple wordsTypical job here
TerraformDescribes what should exist, then makes it exist"We need 10 VMs, 2 networks, a GPU node pool and an S3 bucket" in OpenStack or Kubernetes
AnsibleRuns a checklist of steps on machinesHarden servers, install agents, set config files, patch Ubuntu
JujuA robot operator for big softwareInstall, connect, scale and upgrade OpenStack, Ceph, Kubernetes and COS
Azure DevOpsThe conveyor belt that runs the othersStore code, run tests, require approvals, then run Terraform / Ansible / app deploys

One-line summary: MAAS and Ubuntu build the machines, Juju builds the cloud on them (Ceph, OpenStack, Kubernetes), NVIDIA GPUs power the AI work, Terraform, Ansible and Azure DevOps let teams change things safely through code, Keycloak, Vault, PAM and the SIEM keep it secure, and Prometheus, logs and Grafana show you whether it is all healthy.
